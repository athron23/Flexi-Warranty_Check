# Flexi Warranty Check

เว็บเก็บ Serial Number คอมพิวเตอร์และอุปกรณ์ไอที สำหรับ บริษัท เฟล็กซี่ โซลูชั่น จำกัด (นครราชสีมา)
ใช้รับสินค้าเข้า ขายออก และเช็คประกัน ด้วยเครื่องยิงบาร์โค้ด ลูกค้าเช็คประกันเองได้โดยสแกน QR Code หรือบาร์โค้ดผ่านมือถือ

**เริ่มติดตั้งที่ [SETUP-TH.md](SETUP-TH.md)**

## มีอะไรบ้าง

| หน้า | ใครใช้ | หน้าที่ |
|---|---|---|
| `docs/index.html` | พนักงาน (ต้องล็อกอิน) | รับเข้า, ขายออก, เช็คประกัน, สต็อก, ส่งออก CSV |
| `docs/check.html` | ลูกค้า (ไม่ต้องล็อกอิน) | พิมพ์ Serial หรือสแกน QR/บาร์โค้ดเพื่อดูสถานะประกัน |
| `docs/qr.html` | พนักงาน | พิมพ์ป้าย QR ติดใบรับประกันหรือตัวเครื่อง |

หน้าลูกค้าเห็นเฉพาะ ชื่อสินค้า ยี่ห้อ ประเภท สถานะ และวันสิ้นสุดประกัน ไม่เห็นชื่อ เบอร์โทร หรือเลขที่ใบขายของลูกค้า

## โครงสร้าง

```
docs/                 เว็บทั้งหมด (ไฟล์ static ไม่ต้อง build)
  config.js           ตั้งค่าร้านและ Supabase (แก้ไฟล์นี้ไฟล์เดียวตอนติดตั้ง)
  js/data.js          ชั้นเก็บข้อมูลกลาง ทุกหน้าเรียกข้อมูลผ่านไฟล์นี้เท่านั้น
  vendor/             ไลบรารีที่ใช้ (supabase-js, html5-qrcode, qrcode-generator)
supabase/schema.sql   สคริปต์สร้างตาราง สิทธิ์ และฟังก์ชันเช็คประกันสาธารณะ
tests/                ทดสอบฐานข้อมูลและหน้าเว็บ
legacy/               เวอร์ชันแรกที่รันในแชท Claude (เก็บไว้อ้างอิง ใช้งานนอก Claude ไม่ได้)
```

## โหมดทดลอง

ถ้า `SUPABASE_URL` และ `SUPABASE_ANON_KEY` ใน `docs/config.js` ยังว่าง เว็บจะทำงานในโหมดทดลอง
ข้อมูลเก็บในเบราว์เซอร์เครื่องนั้นเท่านั้น ไม่มีล็อกอิน ใช้ลองหน้าตาได้ ห้ามใช้งานจริง

ลองในเครื่อง: `npm run serve` แล้วเปิด http://localhost:8080

## ความปลอดภัย (สรุป)

- ตารางข้อมูลเปิดให้เฉพาะพนักงานที่ล็อกอินเท่านั้น คนทั่วไปเข้าตารางตรง ๆ ไม่ได้
- ต้องปิดการสมัครสมาชิกเองใน Supabase (ดู SETUP-TH.md ข้อ 4) ไม่เช่นนั้นใครก็สมัครแล้วเข้าได้
- หน้าลูกค้าเรียกฟังก์ชัน `check_warranty` ซึ่งคืนข้อมูลที่ไม่ใช่ข้อมูลส่วนตัวเท่านั้น และจำกัด 30 ครั้ง ต่อ 10 นาที ต่อ IP
  ลดการสุ่มเดา Serial ได้ แต่กันไม่ได้ทั้งหมด
- กุญแจ `anon` ใส่ใน `config.js` ได้ เพราะเป็นกุญแจสาธารณะ ห้ามใส่ `service_role` หรือ secret key

## ทดสอบ

```
npm install
npx playwright install chromium
npm test
```

`test:db` รัน schema บน Postgres จำลอง ตรวจสิทธิ์และการจำกัดจำนวนครั้ง
`test:e2e` เปิดหน้าเว็บในเบราว์เซอร์จริง ทดสอบรับเข้า ขายออก เช็ค ส่งออก CSV พิมพ์ QR และอ่าน QR กลับจากรูป
ทั้งโหมดทดลองและโหมด Supabase (ตัวจำลองเซิร์ฟเวอร์ ไม่ได้ต่อ Supabase จริง)

## ที่ยังไม่ได้ทดสอบกับของจริง

- การเชื่อม Supabase จริง (ล็อกอิน, อัปเดตสด, ฟังก์ชันเช็คสาธารณะผ่านอินเทอร์เน็ต)
- การสแกนด้วยกล้องมือถือจริง โดยเฉพาะบาร์โค้ดเส้น ทดสอบแล้วเฉพาะการอ่าน QR จากรูป
- เครื่องยิงบาร์โค้ดรุ่นที่ร้านใช้ (ทดสอบด้วยการจำลองการพิมพ์ตามด้วย Enter)

## ย้ายไปรันบน NAS ในอนาคต

หน้าเว็บทั้งหมดเรียกข้อมูลผ่าน `docs/js/data.js` ไฟล์เดียว
เมื่อมี NAS ให้เขียน backend ตัวใหม่ในไฟล์นั้น (ดูฟังก์ชัน `makeDb`) หน้าตาและตรรกะประกันใช้ต่อได้
แต่ต้องย้ายข้อมูลและทำระบบล็อกอินใหม่ ไม่ใช่แค่เปลี่ยนค่าตั้งค่า

## ที่ยังไม่มี

ประกันตลอดอายุ, ลบหรือแก้ชื่อประเภทที่เพิ่มเอง, นำเข้าข้อมูลจากไฟล์ CSV, แยกสิทธิ์ผู้ดูแลกับพนักงานหน้าร้าน
